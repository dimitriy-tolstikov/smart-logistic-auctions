# УЛ Лайт — Аукционы

SPA для работы с грузовыми аукционами по OpenAPI-схеме (`openapi.auctions.v0.json` — источник правды).
Backend не нужен: все запросы `/api/v1` в dev-режиме обслуживает MSW-мок, реализованный строго по схеме
и реально меняющий состояние после mutations.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
```

Требования: Node 20+ (разработка велась на Node 24), npm.

Остальные команды:

```bash
npm run build      # продакшен-сборка (tsc + vite)
npm run lint       # eslint
npm test           # vitest — юнит-тесты чистой логики и моков
```

## Стек

React 19 · TypeScript (strict) · Vite · TanStack Router (file-based) · TanStack Query ·
React Hook Form + Zod · MSW · Feature-Sliced Design · Zustand · Tailwind 4 · shadcn/ui (Radix) ·
openapi-typescript + openapi-fetch.

## Что внутри

- **Список аукционов** (`/`): пагинация, skeleton/empty/error states, prefetch детали по hover,
  фильтры с синком в URL search params (Zod-валидация с безопасными fallback),
  адаптивная вёрстка (desktop/mobile).
- **Детальная страница** (`/auctions/:uuid`): основные данные, организатор, контакты,
  маршрут со всеми точками, груз и требования к ТС, условия оплаты, параметры торгов
  (текущая/доступная цена, min/max/step), состояние своей ставки, история ставок
  (участники, цена с/без НДС, место, победитель, отменённые с причиной, empty state,
  скрытая история). Учитываются `can_set_bet`, `hide_bets_history`,
  `hide_points_address_and_contacts`, `no_view_cargo_price`.
- **Форма ставки** (`/auctions/:uuid/bet`, открывается по ссылке): RHF + Zod,
  валидация обязательности/min/max/сетки шага, подсказки по доступной цене и шагу,
  mutation → инвалидация list/detail/bets, success/error toast (sonner),
  маппинг 422 на поле формы.

## Мок (MSW)

- Детерминированный генератор (mulberry32): 48 аукционов во всех статусах и типах,
  со связными данными (торговый статус выводится из статуса аукциона, текущая цена =
  лучшая активная ставка, побеждающая моя ставка — place 1 и т.д.).
- Стор с фильтрами/пагинацией/сортировкой и логикой ставок: валидация min/max/step,
  пересчёт текущей цены, доступной ставки, мест и торгового статуса после `POST /bets`.
- В dev-шапке — переключатель мок-сценариев (401/503) для проверки error states.
- Фильтры синкаются в URL; «← К списку» с детальной возвращает к тем же фильтрам
  (sessionStorage, per-tab).

## Как проверял

- `npm test` — 106 тестов: search params parsing, request builder, мапперы/viewmodel,
  zod-схема и правила шага ставки, форматирование цены, связность сгенерированных данных,
  стор моков (фильтры, ставки, пересчёт мест), сквозной тест apiClient → MSW.
- Ручные сценарии в браузере: фильтрация (в т.ч. по датам и «Не определён» типу),
  пагинация, возврат «← К списку» с фильтрами, детальная со всеми флагами скрытия,
  ставка: ошибка вне сетки шага → успешная ставка → обновление цены/статуса/истории,
  error states через мок-сценарии 401/503.
- `npm audit` — 0 уязвимостей.

## Ограничения

- Мок осознанно шире контракта в одном месте: фильтр `auc_type` принимает `Unknown`
  (в `AuctionListRequest` схемы его нет) — помечено комментарием в коде.
- В detail DTO нет `is_accredited`/`is_admitted` — допуск выводится из
  `admitted_organizations`; «своя» ставка в истории определяется сверкой организации
  с этим списком (в `BetItem` признака нет).
- MSW работает только в dev-режиме; собранный бандл без живого API данных не покажет.
- Подробности о работе с AI — в `AI_USAGE.md`.
